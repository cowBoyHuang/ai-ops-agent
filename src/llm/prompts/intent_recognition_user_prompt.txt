【打分标准】

每个意图从 4 个维度打分（0-1 分）：

1. 语义匹配度 (权重 0.5)
- 问题语义与意图的匹配程度
- 1.0 = 完全匹配，0.0 = 完全不匹配

2. 关键词匹配度 (权重 0.3)
- 是否包含意图相关的关键词
- 1.0 = 包含多个强相关关键词，0.0 = 无相关关键词

3. 上下文相关性 (权重 0.1)
- 是否符合对话上下文（如果没有上下文则为 0.5）
- 1.0 = 高度相关，0.0 = 完全不相关

4. 问题类型匹配 (权重 0.1)
- 问题类型是否符合意图特征
- 1.0 = 完全符合，0.0 = 完全不符合

【意图定义】

意图1: 业务咨询
- 定义: 咨询系统功能、代码逻辑、业务规则等
- 关键词: 支持、逻辑、规则、功能、如何、是否、代码、实现
- 问题类型: 咨询类（是否、如何、为什么）

意图2: 线上问题排查
- 定义: 线上故障、错误、失败等问题排查
- 关键词: 失败、错误、问题、故障、排查、为什么不行、一直
- 问题类型: 描述问题/求助类
- 追问识别: 若“最近历史记录”中已出现 traceId/orderNo/日志查询结果/上轮排障结论，且当前问题是在追问细节（如“哪位乘机人”“实际年龄”“还有哪些”），应优先判定为线上问题排查。

【历史优先判定规则（必须执行）】
1. 若“会话上下文锚点”中存在 trace_id 或 order_id，且当前问题属于字段追问（例如“bizErrorCode是什么”“错误码是多少”“是谁被拦截”“年龄是多少”），则“线上问题排查”的 semantic_match 与 context_relevance 不得低于 0.8。
2. 若历史记录包含上轮排障输出（根因、证据链、日志结论），当前问题即使是短问句，也按排障追问处理。
3. 只有在“无 trace_id/order_id 且无排障历史”时，`xxx是什么` 这类问法才倾向“业务咨询”。
4. 禁止因为“是什么”问法就直接判定业务咨询，必须先检查历史上下文。

【示例（用于校准）】
- 示例A（应判 线上问题排查）:
  - 最近历史: 已有 traceId=flight_supply_open_api_...，且上一轮结论是“生单失败，subErrorCode=39”。
  - 当前问题: “bizErrorCode是什么”
  - 结论: 这是对同一排障会话的字段追问，判“线上问题排查”。
- 示例B（应判 业务咨询）:
  - 最近历史: 无 traceId/orderNo、无排障记录。
  - 当前问题: “bizErrorCode是什么”
  - 结论: 纯概念咨询，判“业务咨询”。
